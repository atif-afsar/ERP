# Phase 12 — AI Assistant Connected to ERP Data

## Objective

Connect the existing AI assistant to real, permission-filtered ERP data.

## Security principle

The AI must never receive unrestricted database access.

Architecture:

```text
User
 ↓
AI request
 ↓
authenticated user + tenant context
 ↓
allowed tools/functions
 ↓
validated query
 ↓
permission-filtered data
 ↓
LLM
 ↓
answer
```

## Example tools

- get_student_summary
- get_attendance_report
- get_outstanding_fees
- get_exam_results
- get_staff_summary
- search_knowledge

## Do not allow

Raw arbitrary SQL generated by the model against production data.

## Data minimization

Only provide the fields needed for the requested answer.

## Audit

For sensitive queries log:

- user
- tenant
- tool called
- timestamp
- success/failure

Avoid storing unnecessary personal data in prompts/logs.

## Acceptance examples

A teacher can ask:

> Which students in my class were absent this week?

A finance user can ask:

> Show outstanding fees by class.

A parent can ask:

> What is my child's attendance this month?

The answer must respect that user's permissions.

## Exit criteria

AI answers come from real data and cannot cross tenant/role boundaries.
