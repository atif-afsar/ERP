# 1. Purpose

This document defines the complete communication and notification architecture for the ERP.

The communication system connects:

```text
Admin
Teacher
Student
Parent
Finance
System
```

with important events across the platform.

The architecture must support:

```text
In-App Notifications
Email
SMS
WhatsApp
Push Notifications
Announcements
Automated Reminders
Communication Templates
Delivery Tracking
Notification Preferences
```

---

# 2. Core Principle

Notifications are **events generated by the system**, not independent business logic.

Example:

```text
Fee becomes overdue
        ↓
Business Event
        ↓
Notification Engine
        ↓
Select Template
        ↓
Select Recipients
        ↓
Select Channels
        ↓
Send
        ↓
Track Delivery
```

The notification system must not duplicate business logic already owned by other modules.


```text

```


# 112. Notification Engine Rules

The engine should:

```text
Receive Event
Resolve Tenant
Resolve Recipients
Check Preferences
Select Template
Render Message
Select Channels
Create Delivery Jobs
Send
Track Status
Retry Where Appropriate
Audit
```

---

# 113. Notification Engine Must Not

It must not:

```text
Change Fee Amounts
Mark Payments Successful
Modify Attendance
Publish Results
Approve Admissions
```

Business decisions belong to their respective modules.

# 144. Final Principle

> **The Notifications & Communication module is an event-driven delivery layer. Business modules generate authoritative events; the notification engine resolves recipients, preferences, templates and channels; delivery is asynchronous, idempotent, auditable and tenant-isolated. Communication failure must never corrupt the underlying business transaction.**
