## 1. Control Counting Methodology

To prevent artificial inflation from dynamically generated table rows or duplicate loop iterations, the control counting follows this strict taxonomy:
1. **Unique Interactive Element Identity:** A control is counted once per distinct screen context (unique action, input, select, button, or tab).
2. **Repeated Table-Row Controls:** Repetitive table action controls (such as "View", "Edit", "Mark Attendance", "Approve", "Download") are counted once per control archetype per screen table, not multiplied by the number of database rows.
3. **Global Shell Controls:** Application shell controls (sidebar drawer toggles, notification bell, user profile menu, sign-out) are cataloged as persistent shell controls.
4. **Modals & Dialogs:** Interactive controls within modals (e.g., plan creation, student admission, leave request, notice dispatch) are counted within their respective screen contexts.
